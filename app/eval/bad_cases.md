1. faithfulness：+3.5%（小幅提升）

结论： Prompt 约束能减少幻觉，但不是万能药。要进一步提升忠实度，需要从检索源头减少低相关文档的混入。

2. answer_relevancy：仍然 NaN

原因：部分样本因检索结果为空，导致 RAGAS 无法计算该指标。

虽然我们已修复检索为空时返回固定拒答字符串，但 answer_relevancy 仍然为 NaN。这通常是因为 RAGAS 内部的评分 LLM 在计算相关性时，对某些极短或固定格式的拒答答案无法生成有效评估。

后续解决方向：

对检索结果为空的情况，跳过 answer_relevancy 计算（但当前 RAGAS 版本可能不支持排除特定样本）。
或在评估前，手动剔除那些标准答案为“无法回答”的样本，仅对可回答的问题计算该指标。
结论： 这不是系统功能问题，而是评估工具在极端样本下的局限性。

3. context_recall：+4.9%（明显提升）

原因：查询改写开始发挥作用。

我们在评估脚本中增加了 rewritten_query 的提取和记录，但更重要的是，优化后的管线中查询改写正在生效——模糊的、口语化的问题被改写成了更适合检索的书面语，从而扩大了有效召回范围。

结论： 查询改写对提升召回率有直接贡献。后续可以通过分析 rewritten_query 来进一步优化改写策略。

4. context_precision：0.4369（较低，首次获取）

原因一：RAGAS 终于成功计算了该指标。

通过修正 ground_truth 格式和确保 answer 非空，RAGAS 的条件满足了，成功输出该指标。

原因二：精确率确实偏低，主要原因是当前管线未开启重排序。

context_precision 衡量的是“检索返回的文档中有多少是真正相关的”。你的管线目前使用的是 accurate_norerank 模式（enable_rewrite=True, enable_rerank=False），虽然召回的文档变多了（召回率提升），但其中也混入了更多低相关文档，导致精确率被稀释。这是召回率与精确率之间的经典权衡。

结论： 首次拿到精确率数据是非常宝贵的。通过开启重排序或进一步提高相似度阈值，这个指标仍有巨大提升空间。

5. 拒答成功率：95%（非常优秀）

原因：多层防护策略生效。

相似度阈值过滤：将大量低相关文档拒之门外，让 LLM 收不到“可编造”的素材。

评估脚本优化：检索为空时直接返回固定拒答字符串，避免 LLM 空输入导致不可控输出。
95% 的拒答成功率意味着：在知识库没有答案时，系统几乎不会胡说八道。 这是生产级 RAG 系统的核心指标之一。

结论： 你的 RAG 系统已经具备了可靠的“诚实度”。这在法律、医疗、金融等高精度场景中是决定性的能力。
