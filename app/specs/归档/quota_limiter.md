## ✅ 做了什么

- **按【用户】【每日】计数** —— Redis key = `quota:{user_name}:{YYYY-MM-DD}`，`INCR` + 首次 `EXPIRE 86400`（Lua 原子）
- 额度来自 `permission.ROLE_QUOTA`（free 100 / premium 10000 / admin 不限）

## 🟡 做到哪 / 缺什么

- 🔴 **匿名请求完全绕过**（见下）
- 🔴 **没有"全局日级"这一层** —— 每个方法第一个参数都是 `user_name`，**没有任何跨用户记账键**
  ⇒ **第 4 层限额不存在 ⇒ 熔断无对象可触发**
- ⬜ **零测试覆盖**（`docs/说明/测试.md` §六 **#8**）
- ✅ **R2.2 恢复条件【已实测】（2026-10-02 补 · `①b` 清陈旧锚点）** —— `EXPIRE 86400` **确实设上了**：

  ```bash
  docker exec redis-rag redis-cli --scan --pattern 'quota:*' | head -5 | while read k
  do echo "$k $(docker exec redis-rag redis-cli TTL "$k")"; done
  # 实测：共 85 个 quota:* 键；抽 5 个 ⇒ TTL = 82559 / 82581 / 83912 / 83048 / 83048
  #      全部 ∈ (0, 86400)，**没有一个是 `-1`**（`-1` = 没设 TTL）
  ```

  ⇒ TTL **在递减、且都略小于 86400**（写入后已过一段时间）⇒ 「**首次 `INCR` 时设 `EXPIRE`**」**成立**。
  ⚠️ **边界（⛔ 别读大）**：这只证明 **TTL 被设上**。「**到点真的消失**」另跑了一次 3 秒探针
  （`SET probe:ttl-check 1 EX 3` ⇒ 5 秒后 `EXISTS=0`）—— 但**那证明的是 Redis 自身会过期**，
  **不是本文件这条路径跑到过 86400 秒的终点**（要等满一天才能观测，本轮没等）。

  📌 **为什么拖到今天**：这条是 `①b ` 的计划点要求顺带核掉的
  （`app/billing/specs/token_tracker.md:1090-1091` 原文：「一并核掉（同一件事）」），
  但  后来走的是 **PG 路线**⇒ 当时**没人核、也没人说明为什么不核**。2026-10-02 补上。
