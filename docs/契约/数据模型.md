## 一 · `documents` —— RAG 知识库 ⭐

```sql
CREATE TABLE IF NOT EXISTS documents (
    id           SERIAL PRIMARY KEY,
    content      TEXT NOT NULL,
    source       TEXT,
    embedding vector(1024), -- pgvector（B 段：1536 → 1024）
    requested_by TEXT NOT NULL DEFAULT 'anonymous'    -- 归属人
);
```

| 字段 | 说明 |
|---|---|
| `id` | 自增主键 |
| `content` | 文档正文（**分块后的块**，不是整篇） |
| `source` | 来源标识。实测形态如 `eval_dataset.json#23` · `eval-gap-fill-*` |
| **`embedding`** | **`vector(1024)`** —— 由 DashScope `qwen3.7-text-embedding-flash` 生成（**B 段：1536 → 1024**）。⚠️ **维度写死在建表语句里**（`app/core/db.py`），换 embedding 模型**必须改这里** |
| `requested_by` | 归属用户名。默认 `'anonymous'` |

> 🔴 **⚠️ 多用户隔离是【打折的】**：注释写着「所有查询和修改都带上当前用户的 ID 进行过滤，
> 从而实现多用户数据隔离」—— **但实测多数检索端点没有按它过滤**。
> 这条作者已裁「**不动**」（属 M5 裁决范围），登记在。

## 二 · 认证 · `api_keys`

```sql
CREATE TABLE IF NOT EXISTS api_keys (
    id         SERIAL PRIMARY KEY,
    user_name  TEXT NOT NULL,
    key_hash   TEXT NOT NULL UNIQUE,     -- ⭐ 存的是 SHA256，不是明文
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP NOT NULL,
    is_active  INTEGER DEFAULT 1         -- 可空：老行为 NULL，COALESCE 放行
                                         -- 🔴 是 INTEGER(0/1)，⛔ 不是 BOOLEAN：
                                         --    `issue_api_key.py --revoke` 写 `SET is_active = 0`
);
```

> ### 🔴 `is_active` 的**唯一来源是本仓 DDL** —— ⛔ 不是某个迁移
>
> `app/core/db.py` 建表语句 + 启动期那句 `ALTER TABLE api_keys ADD COLUMN`（老库补列）。
>
> ⛔ **别写成「由迁移 `828721f77ef2` 加上」** —— 那份迁移在真库上**从没生效**。
> 🔴 **踩了会怎样**：真库 `api_keys` 只剩 5 列时，`app/access/auth.py` 那句
> `COALESCE(is_active, 1) = 1` ⇒ `UndefinedColumn: column "is_active" does not exist`
> ⇒ **每次 API-Key 认证 503**，且限流/额度两道闸**同时 fail-open**（**静默**）。
> ⚠️ **用例不会替你发现** —— 它们用**自建的表**跑（自带这一列）⇒ **一条都不会红**。
>
> ✅ `verify_api_key()` **会过滤 `is_active`**（契约 D）—— 判据用 `COALESCE(is_active, 1) = 1`，
> 所以 `NULL` 的老行**照样通过**。⚠️ 守卫 ⇒ `app/tests/test_auth_api_key_active.py`（有反证用例）。
>
> 🔴 **装了 `alembic` 之后多出一条新雷**：`app/alembic/versions/` 那份 `init` 迁移的 `upgrade()`
> **会 `drop_column('documents', 'requested_by')`**（**多用户隔离的承重列**）
> ⇒ 跑一次 `upgrade head` 就把它删掉、**且不报错**。
> 状态与。
>

## 二·附 · 登录账号 · `login_users`（**第 8 张** · 补录）

```sql
CREATE TABLE IF NOT EXISTS login_users (
    user_name     TEXT PRIMARY KEY,                 -- ⭐ 一个用户名【一行】
    password_hash TEXT NOT NULL,                    -- `pbkdf2_sha256$轮数$盐$哈希`
    is_active     BOOLEAN NOT NULL DEFAULT TRUE,    -- ⚠️ 与 api_keys 那个 INTEGER 不同，见下
    created_at    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    expires_at    TIMESTAMP                         -- ⭐ NULL = 永不过期
);
```

> ### 🔴 它与 `api_keys` 是【两件事】，⛔ 别合并
>
> | | `api_keys`（§二） | `login_users`（本节） |
> |---|---|---|
> | 通行证 | **`X-API-Key`** | **用户名 + 口令 ⇒ JWT** |
> | 粒度 | 一个用户名**可有多把**，每把带自己的 `expires_at` / `role` | **一个用户名一行** |
> | `expires_at` | **`NOT NULL`**（必须给） | **可空** —— `NULL` = **永不过期** |
> | `is_active` | **`INTEGER`**（0/1） | **`BOOLEAN`** |
>
> ⇒ **一个身份、两张通行证**，最终都解析成**同一个 `user_name`**
> （收口在 `app/routing/deps.py::get_current_user_hybrid`）。
>
> 🔴 **`is_active` 的类型【故意不同】，⛔ 别"顺手统一"**：
> `api_keys` 那列用整数，是为了兼容**加列之前写进去的老行（NULL）**（`COALESCE(is_active,1)=1`）；
> 本表是**新表、列 `NOT NULL`** ⇒ `NULL` 在这儿只可能是坏数据。**两种语义，⛔ 不是不一致。**

> ### ⚠️ 三处看代码会误判的
>
> 1. 🔴 **「角色 `role` 在这张表里」** —— ⛔ **不在**。角色由 **`api_keys.role`** 定；
>    **库里查不到的新用户名默认是 `FREE`**（`app/access/permission.py::_hardcoded_role`）
>    ⇒ **建号时 ⛔ 不需要顺手往 `api_keys` 插一行**。
> 2. 🔴 **「`admin` / `test_user` 在这儿有行」** —— ⛔ **没有**，它们由 **`.env`** 管。
>    本表**实测 `0` 行** ⇒ **还一个账号都没建过**。
> 3. ⚠️ **「口令是明文存的」** —— ⛔ 存的是 **`pbkdf2_sha256$轮数$盐$哈希`**；
>    **轮数与盐写在串里** ⇒ 将来把轮数调大**不会让已有口令失效**。
>
> **谁在读写它**：`app/access/login_users.py`（`authenticate_from_db` · `login_account_blocked` · 那两句 `INSERT`）·
> 调用方 `app/access/auth.py`。⚠️ **改 `login_account_blocked` 那套口径之前，先读它自己的 docstring。**

## 六 · 向量索引的类型

| 项 | 值 |
|---|---|
| **access method** | `hnsw` |
| **代码里的声明处** | `app/core/db.py::_VECTOR_INDEX_AM` —— **全仓唯一的定义处**，⛔ 别在别处再写一个字面量 |
| **活库** | `documents_embedding_idx` —— 由**启动时的自愈段**保证与代码一致 |
| **距离算子** | `vector_cosine_ops` ⇒ 检索用 `<=>`（余弦**距离**） |

⚠️ `search_similar` 返回的那一列是 **`1 - (embedding <=> q)`** ⇒ 是**相似度**（⛔ 不是距离）。

### 🔴 为什么它现在【不会再和代码漂移】

那句 `CREATE INDEX **IF NOT EXISTS**` **改不动已经存在的索引** —— 名字一旦被占，整条就空转。
本仓为此漂移过一段时间（代码里写 `ivfflat`、活库是手工建的 `hnsw`，两边不一致而**没有任何东西盯着它**）。

⇒ 现在 `create_table()` 在建完之后**读 `pg_am.amname` 验类型**：
与 `_VECTOR_INDEX_AM` 不符就 `DROP` + 重建。
⇒ **改索引类型 = 改那一个常量**，下次启动自动迁移。
⛔ 不需要手工 SQL；⛔ 不需要 `alembic`（那条链本仓已明文作废）。

### ⚠️ 两个操作上的前提（⛔ 少一个就会静默出错）

- **`pgvector` 必须 ≥ 0.8** —— 低于它，`iterative_scan` 那两个 GUC **不存在**，
  而 `SET` 会被 PG 当**占位符**静默收下、**`SHOW` 还会回设定值**
  ⇒ 防护**空转，且一条门都不会红**。
  兜法：`assert_pgvector_supports_iterative_scan()` 在**启动时拒绝启动**。
- **近似索引"先扫索引、后套 `WHERE`"** ⇒ 带 `requested_by` 过滤的检索会**少于 `LIMIT`**。
  兜法：两句向量 SQL 之前都调 `enable_ann_iterative_scan()`（`SET LOCAL`，两处调用点见 `app/core/db.py`）。
