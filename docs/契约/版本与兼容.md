## 二 · ⬜ 建议的约定（**待作者裁**）

> ⚠️ **以下全部是【提议】，不是现状。** 作者批准后，把这一节改成"约定"。

### 2.1 什么时候该打一个 tag

**判据**：**"这一版，别人可以拿去用了"** —— 不是"代码写完了"。

| 该打 tag | 不该打 tag |
|---|---|
| 阶段②「本机跑通」这类**可验证的里程碑** | 每天的零散提交 |
| **链接发出去之前**（上公网那一刻） | 还在动的功能 |
| 四硬门补齐、后端阶段收口 | 文档整理 |

### 2.2 版本号怎么编

**建议：`v0.x.y` 起步** ——
理由：⚠️ **四层限额落了 3 层、熔断只有 1 条 key、前端为零**（见  功能现状表）
⇒ **现在就打 `v1.0.0` 是没有依据的**（这与 `README.md` 删掉「生产级」是同一个道理）。

| 位 | 什么时候 +1 |
|---|---|
| `x` | **破坏性变更**（见 §三） |
| `y` | 向后兼容的新功能 / 修复 |
| `z` | 只改文档 / 只改内部 |

### 2.3 什么算**破坏性变更**（**核心**）

| 是 | 不是 |
|---|---|
| 删掉或改名一个端点 | 新增端点 |
| 改一个**必填**字段的名字 / 类型 | 新增**可选**字段 |
| 把**可选**字段改成**必填** | 改默认值（⚠️ **例外见下**） |
| 改**错误码**的取值或 HTTP 映射 | 改错误**文案** |
| 改**响应体的结构**（字段消失 / 换位置） | 新增响应字段 |
| 改**认证方式**（如去掉 API Key） | 新增一种认证方式 |
| 改**配额/限额的语义**（别人能跑的次数变了） | — |

#### ⚠️ 两条本仓特有的、**容易被当成"无害"的破坏性变更**

1. **改 `QuestionRequest` 的默认值** —— 🔴 **本仓已经踩过一次**：
   `generate_answer` 默认 `False`，某天若改成 `True`，
   **所有不传这个字段的调用方会突然开始花钱**（而且是在他们不知情的情况下）。
   ⇒ **改默认值要当成破坏性变更。**
2. **改 `mode` 的默认值或枚举取值** —— 同理（现在是 `accurate`）。
   ⚠️ 而 `accurate` **需要 torch** ⇒ 若将来镜像里装回 torch / 或去掉，**行为会变**。

### 2.4 怎么通知

⬜ **建议**（未定）：

| 在哪 | 写什么 |
|---|---|
| `CHANGELOG.md` | **每个版本一个 `## [x.y.z] - YYYY-MM-DD` 段**（现在是 Keep a Changelog 格式，只是没版本号） |
| 破坏性变更**单独一节** | `### ⚠️ Breaking` —— 别混在 `Changed` 里 |
| `README.md` | 「已知限制」表里同步 |

### 2.5 弃用流程

⬜ **建议**（未定）：

```
① 标 deprecated（文档 + `/openapi.json` 的 description + 代码注释）
② 保留 ≥ 1 个版本周期，期间【正常工作】
③ 移除时，在 CHANGELOG 的 Breaking 段写明
```

⛔ **本仓现在一个 deprecated 标记都没有** —— 因为**从来没删过端点**。
