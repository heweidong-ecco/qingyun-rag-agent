## 怎么跑（**在服务器上、容器里**）

```bash
cd ~/qingyun-rag-agent
sudo docker compose -f docker-compose.yml -f docker-compose.deploy.yml exec api     python manage_users.py add hr001
```

## 🔴 为什么它【不是】一个 HTTP 端点（§二·①）

给外面发 N 个账号这件事，**建成网页/端点**要额外维护一个**对公网的接口**；
而**它只需要你（能 SSH 上这台机器的人）** 用。
⇒ 收成一条命令 = **公网上根本没有注册入口** ⇒ **不存在"被人刷注册"这个面**。

## ⛔ 这里【不做】自助注册

公开的自助注册 = 谁都能进来刷你的 token。**有意不做**，⛔ 别"顺手"加。

## 口令怎么来

`add` / `set-password` 会**生成一个随机口令**并**只打印这一次**。
⚠️ **它不落任何日志、不进 shell 历史**（是打印到 stdout，你自己复制）。

## `app/tests/test_agent_sse.py`

> 原先写在该模块代码 docstring 里。⚠️ 原样搬来，⛔ 未改写。

`通用/四硬门 §3-A` 的判据是「**逐字出现**」。而**假流式**（后端一次性拿到整段、
前端再用 `setInterval` 切字符）**照样有 `text/event-stream`、照样有 `data:` 帧** ——
计划里那条弱测试（`content-type` + `data:` ≥ 2）**抓不到它**：
后端只发「整段 + `[DONE]`」就是 2 条 `data:`，**照样绿**。

⇒ 本文件把判据钉在**后端出块**这一层，两道：

1. **结构性**（`test_agent_decide_declares_config_parameter` /
   `test_agent_decide_forwards_config_to_the_model`）——
   **真流式的必要条件是节点声明 `config` 并把它转发给模型的流式调用**。
2. **机制性**（`test_graph_streams_one_chunk_per_token` /
   `test_stream_route_emits_one_frame_per_token`）——
   实际数块：**每 token 一块**，不是攒完一次发。

---

## 三条**实测**事实（假模型探针，非推断；探针脚本已随  记档）

| 事实 | 实测 |
|---|---|
| 真流式**不要求**节点是 `async` | 同步节点 + `.stream(msgs, config=config)` ⇒ 6 块、时间戳递增 |
| **不能**把节点改成 `async` | 会让**同步的** `graph.invoke` 直接抛 `TypeError: No synchronous function provided to "agent"` —— 而非流式路径（`/agent/langgraph_chat` · `api_v1.py` · `api_v1_rag.py`）**都在用它** |
| `.stream` 不读 `ChatOpenAI.streaming` 字段 | `_should_stream` 只看 `disable_streaming` + `_stream` 有没有实现 ⇒ **不必动 `llm` 的构造** |

## 一条**没有**在源码里被保证、只被实测钉住的性质

`stream_mode="messages"` 的三个来源（`langgraph/pregel/_messages.py`）本会**重复**：
① `on_llm_new_token`（真·token）② `on_llm_end`（整段）③ `on_chain_end`（节点返回值）。
**实测**（4 个剧本）：② 被 `dedupe` 拦掉、③ **根本没发** ⇒ 每 token **恰好一块**、不重复。
⇒ 这个性质**只在实测里成立**，所以 `test_stream_route_emits_one_frame_per_token`
把它**钉成用例** —— 哪天 langgraph 升级后开始发 ③，这条会红，而不是**悄悄把答案吐两遍**。

## `app/tests/test_ann_iterative_scan.py`

> 原先写在该模块代码 docstring 里。⚠️ 原样搬来，⛔ 未改写。

## 🔴 这个文件为什么长这样（⛔ 别照"常规"把它简化掉）

**旧版是装饰门** —— 它断言 `SHOW ivfflat.iterative_scan == relaxed_order` +
`len(hits) == 3`，而实测**把防护摘掉，它在 `rag_test` 上 80/80 结果一字不变**。
两个根因，都是 实测出来的：

1. `rag_test` 里 301 行**全是 `admin`** ⇒ `WHERE requested_by = 'admin' OR 'public'`
   **全通过** ⇒ 根本不进"过滤 + 截断"那个场景；
2. `rag_test` 上 planner 对宽过滤**选 `Seq Scan`**（实测 `EXPLAIN` 原文），
   而过滤一变窄它又改走 `documents_requested_by_idx`（btree）+ 排序 —— **那条路天生精确**。
   ⇒ **两条路都被堵死：端到端"靠数据自然触发"在这里做不到。**

⚠️ **试过并失败的**（⛔ 别以为没人试）：临时 schema + `SET LOCAL search_path` 把
`search_similar()` 引到一张"只有 ANN 索引"的表上、`enable_seqscan=off` +
`enable_sort=off` 强逼、`hnsw.ef_search` 压到 1、过滤从 2% 到 100%、`top_k` 从 3 放到 50
—— **planner 始终坚持 `Seq Scan`**（小表上"扫到够 `LIMIT` 就停"比走近似索引更便宜）。
⇒ **能不能逼 planner 用 ANN 索引不由我们控制**，把门建在那上面本身就是脆的。
   ⛔ **别为了"看着更像端到端"再加一条依赖 planner 脾气的用例。**

⇒ 所以本文件把那条属性**拆成四道各自能红的门**，⛔ 不依赖 planner 的随机选择：

| 用例 | 钉住什么 | 它怎么红 |
|---|---|---|
| `test_索引类型与代码一致` | 活库索引的 access method == 代码声明的那个 | 自愈段坏了 / 索引被手工改过 |
| `test_防护真的写进去了_而且不是占位符` | 那两句 `SET LOCAL` 的**效果** | 摘掉 / 改名写错 / 值写错 / 跑在旧 pgvector 上 |
| `test_search_similar_确实接了防护` | 那两处**接线** | 删掉 `search_similar` 里那一行 |
| `test_版本自检的边界` | 启动自检的**判据边界** | 阈值写错 / 判据改成会被占位符骗的 `SHOW` |

⚠️ **中间两条是一对，少一条都不成立**：第二条证"有效果"、第三条证"接上了"。
⛔ 只留其中一条，就是本仓 `CLAUDE.md` §六 说的「**拿「动作成功」当「结果正确」**」。

🔴 **不进 CI**：`ci.yml` 跑的是 `-m "not integration and not needs_db"`
⇒ 这四条**只在本机带 `POSTGRES_DB=rag_test` 时跑**。⛔ **别在任何文档里写成"CI 会拦它"**。

## `app/tests/test_approval_events_db.py`

> 原先写在该模块代码 docstring 里。⚠️ 原样搬来，⛔ 未改写。

## 本文件补的是一个【真缺口】，不是"对称好看"

`app/agent/approval_audit.py` 的 `record_decision` 是 **fail-open** 的：

    except Exception as e:
        print(f"[ApprovalAudit] 记录裁决失败（已忽略）: {e}")

⇒ **表名写错 / 列名写错 / 列类型对不上 / SQL 语法错 —— 它一律只往服务端日志打一行，
谁都不会收到红。** 离线那 12 条（`test_approval_events.py`）走的是**假 pg** ——
它证的是「**SQL 被发出去了**」，**不是「PG 认它」**。

⇒ 本文件让那条 SQL **真的在 PG 上跑一次**，并且**从库里读回来**。

## 所以本文件的每一格都要【读回来】才算数

「调用没抛异常」在这里**不是证据** —— 那个函数**本来就不抛**。
因此本文件里**不出现** `record_decision(...)` 之后直接 `assert True` 这种写法。

## 跑之前必须带库名隔离：`POSTGRES_DB=rag_test`

（本仓有前科：R2 冒烟忘带库名，`record_usage` 往**真库**写了 4 行 ——

**本文件写的是 `approval_events`，不隔离的后果比脏数据更重** ——
`approval_events` 是**审计留痕**表：往真库塞一条假裁决 = **假留痕**
（本仓立场：`app/agent/specs/approval_audit.md`「**表里少一条 ≠ 那次裁决没发生**」，
反过来同样成立 —— **表里多一条假的，就是在伪造"批过"**）。

**为什么要防 NULL**：`app/core/db_metadata.py:41` 声明的是
   `Column("is_active", Integer, server_default="1")` —— **没有 `nullable=False`**
   ⇒ 真库里**可能**有 `is_active IS NULL` 的行。
   写成 `WHERE is_active = 1`，那些行会被**静默排除** ⇒ **老 key 集体失效**，
   而用户只看到一句"凭据无效"，**查不到点上**（同 `deps.py` 剥空白那条教训）。
   **现状（实测）**：本机真库 5 行**全是 1，一行 NULL 都没有**
      —— 所以 `COALESCE` 那半句现在是**保险**，不是"已证实的必需"。
      留着它，是因为 NULL 仍然可以由人工 `INSERT` 或别的库产生，而代价是零。

## 本文件在 犯过一次的事故 —— 两条新用例就是照它写的

当时 `app/access/auth.py` 已经按 `is_active` 过滤，而**真库里根本没有这一列**

（`UndefinedColumn`），且限流/额度两道闸**同时 fail-open**。

**而本文件当时全绿。** 为什么：`_run_against_sqlite` 的表是**它自己手写的**，
手写时带了 `is_active`。⇒ 它测的是「**我按文档描述建的表**」，不是「**产品代码将来会跑的那张表**」。
（同族： 那几篇「代理量 / 空清单静默假通过」。）

⇒ 下面两条把表的来源换成 **`app/core/db.py` 的真 DDL** 与 **`app/schema.sql`（线上口径）**：

## `app/tests/test_budget_hard_intercept.py`

> 原先写在该模块代码 docstring 里。⚠️ 原样搬来，⛔ 未改写。

## 测的是什么

作者 裁定：超预算必须**让调用方在响应里看得出"被拒了"**。
改前是**软拦截** —— 塞一条 `ToolMessage` 就 `continue` ⇒ **HTTP 仍 200**，
只有 LLM 自己看得见 ⇒「预算拦住了」这句话**只对 LLM 成立**。

## 为什么不是「在节点里抛异常」

裁定原文写的是「改成抛 `AppException(QUOTA_EXCEEDED)`」。**实测**：
在 LangGraph 节点里 `raise` 会把 checkpoint 留成
`next=('tools',)` + **一条没人回答的 `AIMessage(tool_calls)`**
⇒ 真 provider（OpenAI 口径）**400**，而 `agent` 是入口节点、**每轮都跑**
⇒ **那个 thread 从此废掉**（不是"下次再说"，是"下一次必定 500"）。

⇒ 拦截走 **state** 出来（`budget_intercept`），由**端点层**转成 429 / error 帧。

## 四条轴

| # | 轴 | 用例 |
|---|---|---|
| ① | 节点：不抛、置标志、**答满本轮每个 `tool_call`** | `test_被拦时*` |
| ② | 节点：没被拦时**不许**置标志（否则每次正常调用都 429） | `test_没被拦时*` |
| ③ | 图：被拦 ⇒ `tools` 之后**直接结束**，不回 `agent` 再调一次 | `test_被拦时图在tools之后*` |
| ④ | 端点：非流式 **429** · 流式 **error 帧** | `test_*端点*` |

**串轮守卫**（`test_上一轮的拦截标志不会串到下一轮`）—— `budget_intercept` 是**普通 state 键**
（last-write-wins + 落 checkpoint）⇒ 必须**每轮清零**，否则"上一轮被拦"会让
**下一轮不需要工具的正常提问也返回 429**。

判据（可打印）：
    `venv/bin/python -m pytest app/tests/test_budget_hard_intercept.py -q -p no:warnings`

## `app/tests/test_cancel_propagation.py`

> 原先写在该模块代码 docstring 里。⚠️ 原样搬来，⛔ 未改写。

## 这个文件测的是「最难假完成」的那一件事

硬门 C 的三条判据里，前两条（前端停 / 日志有 cancel）**都能在"其实没停"的情况下成立** ——
前端停可能只是前端不再显示，而后端**还在烧钱**。
⇒ 所以这里**一条都不测前端**，只测**服务端与上游之间**发生了什么。

## 判据为什么钉在 ASGI 层（不是"自己造一个取消"）

**取消是谁发起的？** 不是我们的代码 —— 是 **Starlette 收到 `http.disconnect` 后
取消 `stream_response` 任务**。uvicorn 实测报 `spec_version: "2.3"` ⇒ 走的是
`create_collapsing_task_group` + `listen_for_disconnect` 那条路。

⇒ 如果测试自己 `task.cancel`，那测的是**我假想的取消**，不是**线上真会发生的那次取消**。
本文件直接把 `StreamingResponse` 当成 ASGI app 跑一遍（`await resp(scope, receive, send)`），
`receive` 在**第 N 帧发出之后**回 `http.disconnect` —— 与真服务器走的是**同一段代码**。

## 假上游为什么是「手动迭代器」而不是 async generator

写了 `async def` + `yield` 的假上游，**红不出来**：`asyncio.run` 收尾时会
`shutdown_asyncgens`，把没人关的异步生成器**顺手关掉** ⇒ `finally` 照跑
**"被我们关了"和"被事件循环收尾关了"长得一模一样**（实测：改前 5 条里有 3 条因此假绿）。

⇒ 假上游实现 `__aiter__` / `__anext__` / `aclose`，**故意不是 async generator**。
这样 `closed` 为真就**只能**是**我们的代码调了 `aclose`**。

## 两条链的观测对象不一样，别混

| 链 | 落在哪 | 数什么 |

## 为什么要有这个文件

`assert_model_dimension()` **本身**是测过的（`test_embedding_model_from_env.py`）。
**但它全绿，启动照样可能被一次网络抖动挡住** —— 只要 `main.py` 里**那两类失败被合并处理**。

`app/main.py` 的 `startup_event` 那段（`` B 段接的线）钉的是：

| 失败 | 期望 | 理由 |
|---|---|---|
| **维度对不上** | 🔴 **往上抛 ⇒ 启动失败** | 这才是"响亮地断"。维度不同源时检索**不报错、只是全错**（§2.1） |

⇒ **静默、且没有任何运行时用例会红** ⇒ 必须用静态判据钉住。

`EnvironmentError` / `EmbeddingDimensionMismatch` 这些词**在本文件的注释和 docstring 里就有**
（上面那张表就是）—— grep 会把"注释里提到"当成"代码里写了"。
⇒ 与 `test_pending_approvals_wiring.py` 同一条纪律：**判据要看 AST，不看文本**
（📄 `docs/规范/开发规范.md` §3.1）。

## 本文件保证什么 / 不保证什么

- ✅ **保证**：接线在，且两类失败的处置**没有被合并**
- ✅ **保证**：两个异常类**确实**能被 `isinstance` 分开（这一条是跑出来的，不是读出来的）
- ⛔ **不保证运行时行为** —— "真撞上配错的表，启动会断" 需要真库真模型，
  已**手工实测**过三种情形（断 / 不断 / 不断），记录在本单

## `app/tests/test_response_model_declared.py`

> 原先写在该模块代码 docstring 里。⚠️ 原样搬来，⛔ 未改写。

## 为什么要有这条门

`response_model` **真会裁字段**（不是"只改文档"）—— 反证实测：
把 `return {"a":1,"b":"…"}` 声明成只含 `a` 的模型 ⇒ **实返 `{'a': 1}`**，`b` **被静默吃掉**。
⇒ 所以「补 `response_model`」是**改行为**，而风险是**静默的**：
   前端在用的字段被吃掉，**不会有任何门报错**（页面只是某个格子空了）。

⇒ 这条门挡的是「**以后新加一个页面/端点，却不声明形状**」。

## 它怎么认出「被前端调用的端点」

**两把尺子，都要用**（只用第一把会**空过**）：

1. **页面/JS 里 `fetch(…)` / `getJSON(…)` 的【字面量】**（`app/static/**`）
2. **JS 模块里那些路径【常量】**（`const XXX_PATH = '/api/v1/…'`）
   —— 新页面走 helper 拼路径（`RagRag.buildSearchPath`），
   字面量那条**对它完全空过**（`test_web_pages.py` 自己也写着这一条）。

**不扫 `reference.html` 那种"清单页"** —— 它把 63 条端点**列出来给人看**，
   不是"调用它们"；扫它会一次误报 60 多条。

## 怎么处理"还没补"的

`PENDING` 那张表**显式列出**还没声明的端点 + 理由
**现在绿**，而**新加一个前端端点却漏了声明 ⇒ 当场红**（这才是本门要挡的）。
别把 `PENDING` 当成"允许清单"：它只装**这一批之前就存在**的，
   新加的东西必须**当场补**。

## `scripts/stamp_static_version.py`

> 原先写在该模块代码 docstring 里。⚠️ 原样搬来，⛔ 未改写。

## 它在治什么

根因不是发布错了 —— 是**浏览器缓存了旧的 `authbar.js`、而 HTML 是新的**：
旧 JS 找的是旧挂点（`#auth-in`/`#auth-out`），新版已改名（`#auth-btn`/`#auth-strip`）
⇒ `setHidden()` **对不存在的元素静默跳过** ⇒ **按钮不换字、那一行不露，且不报错**。

⚠️ **为什么本仓躲不掉**：`/static/` 原先**只有 ETag/Last-Modified、没有 `Cache-Control`**
⇒ 浏览器走**启发式缓存** ⇒ **每次发布都可能有人拿到"新 HTML + 旧 JS"**。

## 它怎么治

**把内容哈希写进 URL** ⇒ 内容一变 URL 就变 ⇒ 浏览器**可以放心长期缓存**（配套见 `app/main.py`
那个 `_ImmutableStaticFiles`：`.js`/`.css` 走 `max-age=31536000, immutable`）。
⚠️ **HTML 自己不走长缓存**（它的 URL 不带哈希）—— 它每次协商一次，命中就回 304。

## ⛔ 为什么必须是脚本、而不是"我下次记得改"

手写版本号（`?v=2` → `?v=3`）**必然会被忘**，而忘了之后**表现和现在一模一样**（半新半旧、不报错）
—— 只是更隐蔽，因为你会以为"加了版本号就没事了"。
⇒ 版本号**从文件内容算**，忘不了；再加一条门盯着（`app/tests/test_web_pages.py` 里那条）。

## 用法

```bash
venv/bin/# 就地改（把 8 个页面里的引用刷成当前哈希）
venv/bin/--check  # 只查不改 —— 门里用的就是这条
```

🔴 **改了 `app/static/` 下任何一个 `.js`/`.css` 之后，都要重跑一次它**（门会提醒你）。
