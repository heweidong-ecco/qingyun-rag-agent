# 标记与 emoji 用法

| 项 | 内容 |
|---|---|
| **状态** | ✅ 已立 |
| **触发** | 作者：「**这个用法写成规范，放进开发仓中**」——起因是我新写的那几份压测文档把 `🔴` 当成了通用强调符，与仓库既有写法不一致 |
| **适用面** | 本仓的 `.md`（含导出到产品仓的那些）。⛔ 不适用： · `CHANGELOG.md` 里的**既有条目**（那是留痕，不改写） |

---

## 一 · 一句话口径

> **emoji 是"这一行的角色标记"，⛔ 不是强调装饰。**

记号回答的是「**这一行是什么**」（提示 / 禁止 / 危险 / 已完成 / 指针 / 判据），
⛔ 不回答「这句话多重要」。**想强调就加粗，别加 emoji。**

---

## 二 · 记号表（按角色，⛔ 不按"重要性"）

| 记号 | 角色 | 用在哪 | ⛔ 别用在哪 |
|---|---|---|---|
| `⚠️` | **注意 / 限制 / 容易读错** | 口径的边界、已知限制、"别读成…" | ⛔ 别拿它标"重要" |
| `⛔` | **禁止** | 禁令；句中否定（`⛔ 不是…` / `⛔ 别…`） | ⛔ 别用在"做不到"上（那是 `❌` 或 ⬜） |
| `🔴` | **危险 / 与直觉相反的要紧事实** | 跑错会出事、结论反直觉 | ⛔ **别当强调符**（见 §三·3） |
| `✅` | **已完成 / 可用** | 状态格、交付物 | ⛔ 别拿来当"对"的勾 |
| `❌` | **不可用 / 已删除** | 状态格、数据"不可用" | ⛔ 别与 `⛔` 混用 |
| `⬜` | **未做 / 未实测** | 待办、目标表 | —— |
| `🟡` `🔵` `🟢` | **状态色** | spec 头部那张表 | ⛔ 别进正文 |
| `📄` | **指针**（去哪看） | "判据 ⇒ …" "细则 ⇒ …" | ⛔ 别用它标结论 |
| `📌` | **判据 / 结论** | "判据（可打印）" | —— |
| `⭐` | **最该读的那一条** | 索引里点名 | ⛔ 一个文件里别超过 3 处 |
| `🆕` | **新增** | 当天新增的行 | ⛔ 别当装饰（过一阵它就假了） |

> **纯装饰一律不用**：`📎` `💡` `🔧` `🚫`。

---

## 三 · 四条硬规则

### 1 · 一行最多两个

超过两个时，**保留行首那个（角色）**和**一个句中的 `⛔`/`⚠️`**，其余删掉。

### 2 · ⛔ 不叠字

`🔴🔴` / `⚠️⚠️` / `✅✅` 一律不写 —— 叠字表达的是"更更重"，而**轻重该用词**。

⚠️ **存量 138 处**（`CHANGELOG.md` 24 · `app/routing/specs/api_v1_agent.md` 13 ·  17 …）
**登记不改**（其中大半是留痕）。**新写的⛔ 不许再叠。**

### 3 · 一个文件里 `🔴` 不超过它的 emoji 的 **35%**

🔴 是**最稀缺**的那个记号。一个文件里 `🔴` 占到三成就说明**它在当强调符用**。
> 参照（实测）：**本仓** `⛔` 28% · `⚠️` 24% · `🔴` 19% · `✅` 13%；
> **产品仓** `⚠️` 29% · `⛔` 26% · `🔴` 20% · `✅` 10%。
> ⚠️ `🔴` 明显高于 20% 的文件，值得看一眼它是不是在当强调符。

### 4 · 记号必须"贴着一个角色"

写 `⚠️ **注意**：…` ✅；写 `⚠️ 这个数字**很好看**` ❌（那是装饰）。
一句话：**删掉这个 emoji，句子还读得通吗？** 读得通且**没丢信息** ⇒ 它就是装饰，删掉。

---

## 四 · 三条软规则（做不到不报错，但别反向干）

| # | 规则 | 理由 |
|---|---|---|
| 1 | **标题里最多一个**，且只用于「规矩 / 状态」类标题（`## 🔴 本层特有的规矩`） | 编号小节（`### 4. …`）里别再放 —— 读者靠编号导航，不靠 emoji |
| 2 | **代码块里不放**（shell 注释、示例） | 代码块会被复制去执行；emoji 在里面只是噪音 |
| 3 | **表格单元格里不放多于一个** | 表格的记号应当读成"这一格的状态" |

## 五 · 判据（可打印）

> ⚠️ **必须先剥掉两类东西再数**，否则**门会报到自己头上**（本文件就是活例子 ——
> 它为了讲这些记号，表格里、反引号里**全是记号**）：
> ① **行内代码片段**（`` `🔴` ``）—— 那是**引用**，⛔ 不是使用；
> ② **记号表那几行**（以 `|` 开头且第一个单元格就是记号的）—— 那是**定义**。
> 📌 这是本仓同类教训的第 N 次：**判据的尺子必须能把"讲这件事的文字"排除掉**。

```bash
python3 - 文件1.md 文件2.md <<'PY'
import re, sys, pathlib
INLINE = re.compile(r'`[^`\n]*`')            # 行内代码 = 引用，⛔ 不算
for f in sys.argv[1:]:
    lines = []
    for ln in pathlib.Path(f).read_text(encoding='utf-8').split('\n'):
        cells = ln.split('|')
        # 记号表的数据行：第一格本身就是个记号 ⇒ 那是【定义】，⛔ 不算
        if ln.lstrip().startswith('|') and len(cells) > 2 and E.fullmatch(cells[1].strip()):
            continue
        lines.append(INLINE.sub('', ln))
    body = '\n'.join(lines)
    ms = E.findall(body)
    if not ms:
        continue
    red = ms.count('🔴')
    # 叠字 = **文本里紧挨着**的两个同一个记号（⛔ 不是"序列里相邻"—— 那会把隔了半行也算进来）
    dbl = len(re.findall(r'(🔴|⚠️|✅|❌|⬜||📌|⛔)\1+', body))
    flag = '  <== 🔴 占比可疑（当强调符用了？）' if red >= 10 and red / len(ms) > 0.35 else ''
    print(f'{f:52} 总{len(ms):4}  🔴 {red:3} ({red/len(ms)*100:.0f}%)  叠字 {dbl}{flag}')
PY
```

⚠️ **本文件跑自己时仍是"可疑"的** —— 它必须**列举**这些记号才讲得清。那不是豁免，
是**判据该有的边界**：**"定义记号" ≠ "使用记号"**。真正要看的是**别的文档**跑出来的那一栏。

`🔴` 占比的参照（实测）：**本仓** `⛔` 28% · `⚠️` 24% · `🔴` 19% · `✅` 13%；
**产品仓** `⚠️` 29% · `⛔` 26% · `🔴` 20% · `✅` 10%。

## 六 · 踩过的坑（本条的由来）

新写压测那几份文档时，我把 `🔴` 用成了通用强调符，一屏能出现五六处；连带还犯了三条：

| 坑 | 长什么样 | 后果 |
|---|---|---|
| **🔴 当强调符** | 占比 29%（本仓常态 19%） | 真正危险的那一条**不再醒目** |
| **叠字** | `🔴🔴` | 与全仓 138 处存量同形，但那不是"可以再写"的理由 |
| **标题里带** | `### 4. 🔴 那 3.4 秒…` | 编号小节靠编号导航，emoji 是噪音 |

⚠️ 顺带一条**同类教训**（不是 emoji）：机械删字时**⛔ 别拿整行 `re.sub` 去压空白** ——
会把行首缩进一起吃掉（` ⇒ 改名字前…`）。**判据：改完 `git diff` 里凡是"只该改标点"的行，
⛔ 不该出现缩进变化。**
