## 0 · 怎么重新抓（**因为 `WebFetch` 在本机不可用**）

> 🔴 **实测**：`WebFetch` 报
> 「**Unable to verify if domain … is safe to fetch**」——
> **但本机网络是通的**（`claude.ai` 302 · `diataxis.fr` 200 · **无代理**）。
> ⇒ **是工具自己的"域名安全校验"那条路不通，不是网的问题。**
> ✅ **绕法：用 `curl`** —— 它通。

```bash
curl -sL --max-time 15 "https://code.claude.com/docs/en/memory" -o /tmp/mem.html
# 然后去标签：
python3 -c "
import re,html,sys
s=open('/tmp/mem.html',encoding='utf-8',errors='ignore').read()
s=re.sub(r'<(script|style)[^>]*>.*?</\1>',' ',s,flags=re.S|re.I)
s=re.sub(r'<[^>]+>','\n',s); print(html.unescape(s))
" | grep -A20 "Organize rules"
```

## 一 · Anthropic 官方（**等级：官方原文**）

> 出处：`https://code.claude.com/docs/en/memory`（用 `curl` 取回，**原文照录**）

### 1.1 🔴 大小 —— **这是我们拆分的直接依据**

> **「target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence.」**
>
> **「Files over 200 lines consume more context and may reduce adherence. Claude Code skips a file over 4 MiB.」**

- **200 行 = 目标**（recommendation），不是硬限制
- 超了的**真实代价**：**消耗更多上下文** + ⭐ **降低遵守度**（reduce adherence）
- 硬上限：**4 MiB**（超了整个文件被跳过）

**⇒ 本仓现状：`CLAUDE.md` 557 行 = 官方目标的 2.8 倍。**

### 1.2 ⭐  —— **两种，只有一种真省上下文**

> **「Rules can be scoped to specific files using YAML frontmatter with the `paths` field.
> These conditional rules only apply when Claude is working with files matching the specified patterns.」**
>
> **「Rules without a `paths` field are loaded unconditionally and apply to all files.」**
>
> **「Path-scoped rules trigger when Claude reads files matching the pattern, not on every tool use.」**

```yaml
---
paths:
  - "src/api/**/*.ts"
---
# API Development Rules
- All API endpoints must include input validation
```

| 类型 | 加载时机 | 省上下文？ |
|---|---|:--:|
| 有 `paths` | **Claude 读到匹配的文件时**才触发 | ✅ **真省** |
| **无 `paths`** | **无条件加载**（同 CLAUDE.md） | ⛔ **不省** |

### 1.3 ⚠️ `@import` **不省上下文**

> **「CLAUDE.md files can import additional files using `@path/to/file` syntax.
> Imported files are expanded and loaded into context at launch alongside the CLAUDE.md that references them.」**
> **「…for organization, though imported files still load and enter the context window at launch.」**

⇒ **用 `@import` 拆 CLAUDE.md 是【组织手段】，不是【省 token 手段】。**
⇒ **要真的降低占用，只能【删】或【移进带 paths 的 rules】。**

其它细节：相对路径**相对引用它的文件**解析 · 递归最多 **4 层** · 项目里的外部导入**首次会弹批准**。

### 1.4 官方给的「该放 / 不该放」

> 出处：[How Claude remembers your project](https://code.claude.com/docs/en/memory)
> [Claude Code 记忆文档（镜像）](https://github.com/ericbuess/claude-code-docs/blob/main/docs/memory.md)

| ✅ 该放 | ⛔ 不该放 |
|---|---|
| Claude **猜不到**的 bash 命令 | **代码里能推出来的** |
| 团队**非默认**的代码风格 | 语言/框架的标准约定 |
| **测试怎么跑**（含跑子集） | 长篇教程或散文解释 |
| 仓库礼仪（分支 / 提交 / PR） | **频繁变动的事实** |
| 环境怪癖（必需 env、本地坑） | 凭据（**永不**） |
| 已知的锋利边缘（"跳过这步 X 就坏"） | 一厢情愿的"最好有" |

**⭐ 判据一句话（官方）**：
> **「Would removing this line cause Claude to make mistakes?」** 不会 ⇒ 删。

**官方示例内容含**：project overview · tech stack · commands · code conventions
**architecture rules** · git conventions · security rules。

> 🔴 **注意这里是 `architecture **rules**`（架构【规则】），不是"架构说明"** ——
> 见本文件 §四 的「我们据此做的修正」。

### 1.5 其它官方事实

| 项 | 内容 |
|---|---|
| **加载时机** | **每次会话**都加载（作为 user message 紧跟 system prompt） |
| **`<!-- HTML 注释 -->`** | ⭐ **注入前被剥掉** ⇒ **给人看的备注不花 token**（代码块里的注释保留） |
| **层级** | managed（组织强制）> user（`~/.claude/`）> **project**（`CLAUDE.md` /）> local（`CLAUDE.local.md`）<br>⚠️ **不是覆盖，是拼接**（根 → 工作目录） |
| **子目录 CLAUDE.md** | **按需加载** —— Claude 读到那个目录的文件时才加载 |
| **`/init`** | 官方建议用它生成草稿，**再手工裁**（⛔ 别指望自动生成） |
| **⛔ 不是 enforcement** | 「**CLAUDE.md is context, not enforcement**」——<br>**必须每次发生的事（如"提交前跑凭据门"）该用 hook** |

> 📌 **最后这条与本仓一条老教训完全一致**：
> **「门挂在别处，就等于没有门」**。
> ⇒ **官方说法 + 我们的实测，指向同一个结论。**

## 二 · Diátaxis（**等级：成熟的公开框架** · Canonical/Ubuntu 全公司采用）

> 出处：[diataxis.fr · Start here](https://diataxis.fr/start-here/) · [Application](https://diataxis.fr/application/)

**四类，每份文档只属于一类。**「跨越边界」被称作「**大量文档问题的根源**」。

| 类型 | 回答的问题 | 用户状态 | 性质 |
|---|---|---|---|
| **Tutorial** 教程 | "我想**学会**" | 新手 | 行动（有人带着走） |
| **How-to** 指南 | "我要**做成 X**" | 已会基本 | 行动（直奔目标） |
| **Reference** 参考 | "我要**查 Y**" | 熟练 | 认知（准确、完整、可扫） |
| **Explanation** 解释 | "我想**理解为什么**" | 任意 | 认知（背景、取舍、观点） |

**对文档作者的价值**：它**暴露"混"的地方** ——
> 参考里跑题讲步骤 · 教程里插一大段原理 ⇒ **一眼能看出该拆**。

## 五 · 我们据此做的修正（**调研的直接产出**）

| # | 原以为 | 调研后的结论 |
|---|---|---|
| 1 | CLAUDE.md 该有「架构」 | 🟡 **该有的是「架构【规则】」**（哪套是产品版本 / 别重构哪个文件）**不是架构【说明】** —— 后者属"代码里能推出来的"，官方说**不放** |
| 2 | 用 `@import` 拆 CLAUDE.md | ⛔ **不省上下文** —— 导入文件**照样启动时全加载** |
| 3 | 用  拆 | ✅ **但只有【带 `paths`】的那种才真省**；无 `paths` 的等同 CLAUDE.md |
| 4 | 「200 行」约束 | ✅ **是官方的**（`target under 200 lines per CLAUDE.md file`），且理由是**降低遵守度** |
| 5 | 靠文档保证"每次都做" | ⛔ **官方明确**：CLAUDE.md **是 context 不是 enforcement** ⇒ **该用 hook** |

> ### 🔴 第 5 条值得单独说
>
> 本仓有一条**靠文档写了很久、但一直没做到**的事：**「提交前跑凭据门」**。
> ⇒ **官方说法 + 本仓「八个 PR 跳过留痕门」的前科，指向同一个结论**：
> **写在文档里 ≠ 会发生。要它发生，得做成 hook。**
>
> ⬜ **已登记**：这属于"自动化运维"缺口的同类（`docs/说明/运维.md` §八）。
