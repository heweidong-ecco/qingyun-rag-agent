① 拿到凭据

两条路 —— 看你从哪个入口进来：

入口怎么拿注意
本仓入口 POST /api/v1/auth/login（到期用 /auth/refresh） 要用户名密码；建号走 /admin/create_user
旧入口 ⚠️ 只在 旧平台那条路上存在 —— 本仓那条路上是 404

拿到之后一律放在 X-API-Key 头上。 🔴 创空间那条路上⛔ 别用 Authorization —— 平台会往每个请求里注入它自己的值； 也 ⛔ 不要在任何地方回显请求头。

② 粘一段能跑的

最小的一次调用（内部线那条；尖括号里换成你自己的）：

# 问一句只有本库答得出的问题curl -X POST "<你的主机>/api/v1/rag/search?mode=accurate_norerank" \  -H "X-API-Key: <你的凭据>" \  -H "Content-Type: application/json" \  -d '{"question":"在保设备上门收不收工时费","citations":true,"generate_answer":true}'

⚠️ mode 走 query 参数（四档之一）。默认那一档 = accurate_norerank （改写 + 向量 + BM25 + RRF，不含重排）。

③ 看到真返回

返回长什么样 —— 字段名、结构、每一栏什么意思 —— 在 总览那一页逐字段标着。 这里只说一句：它是真返回，⛔ 不是画出来的样例。

第一个坑：两个默认值是关的

参数默认不给会怎样
generate_answerfalse只回检索结果，没有答案
citationsfalse答案里没有引用 —— 也就没有"点回原文"

要引用，两个都得显式打开（像上面那段 curl 那样）。

第二个坑：流式与非流式不同源

/rag/search 走的是改写 + 向量 + BM25 + RRF 那条完整链； /rag/stream_search 是另一条更轻的链。 ⇒ 同一个问题，两边结果可能不一样 —— 这是现状，⛔ 不是 bug。

第三个坑：状态码与重试

码什么时候你该做什么
401没给凭据 / 凭据失效重新拿
422参数不合法（例如 mode 拼错）改参数 —— ⛔ 它不会静默兜底
429被限速，或额度用尽🔴 看 Retry-After，⛔ 别硬重试

错误体是一层 error 包住的，里面 type / code 两级 —— 给人看的 message 与给机器读的 code 是分开的，⛔ 别去解析 message。
