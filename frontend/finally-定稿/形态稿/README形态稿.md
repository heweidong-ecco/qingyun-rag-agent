## 在这一页上**用到的 `/3` 结构思路**（`编排` §10.1 那四条）

| # | 思路 | 落在本页哪里 |
|---|---|---|
| 1 | **输入与结果同屏** | `.wrap.con` 两栏（左 344px 请求 / 右结果），⛔ 不是"上面填、下面滚" |
| 2 | **阶段轨，且标出有副作用的那一步** | `.rail` 四段（改写 → 召回 → 融合 → 生成），每段留 `—` 位接真 `timing`<br>⚠️ 本页**只读**，没有有副作用的步骤 —— 那一手留给**外部 Agent 编排页**（工具调用那一步） |
| 3 | **次级内容默认收起** | 四处 `<details>`：端点级 · 两组参数对比 · 本次花费 · 检索历史 |
| 4 | **空态即说明** | 答案 / 引用 / 历史：都写清"跑一次之后这里会出现什么"，⛔ 不是空白、更不是假内容 |

## ⚠️ 本稿**明确没做**的（⛔ 别当成缺陷）

- ⛔ **没接线**（按钮不调后端）—— 那是 **⑥ 实施**；本稿只定形态
- ⛔ **没有一个数是真的**（故也没有一个数是编的）—— 硬约束①
- ⛔ **没有 `console.js` 那种"本地模拟"** —— 移植口径 §二明令丢掉

## 为什么第一处选它

1. **能力主线的第一条** ⇒ 它定下来，**外部 Agent 编排页可以复用同一套骨架**；
2. 它对应 `/3` 的 **`console.html` 最完整**（输入 + 参数 + 阶段轨 + 结果 + 引用 + 空态）⇒ **四条结构思路一次全用上**；
3. 它页首那段**用意声明**（`编排` §10.8）**已经写好** ⇒ 正好一起落到页面上；
4. 它是**最能测出**"我们的真结构在 `/3` 的语言里放不放得下"的那一页。
