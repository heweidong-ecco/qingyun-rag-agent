## 二 · 怎么跑

### 2.1 起环境

```bash
docker compose up -d          # ⚠️ 先确认没有评测在跑：docker ps | grep eval ⇒ 空
docker ps --format '{{.Names}}\t{{.Status}}'   # ⇒ rag-api / rag-executor / redis-rag / postgres-rag 全 healthy
```

### 2.2 拿一把 key（🔴 **它⛔ 不进仓**）

```bash
export RAG_API_KEY="$(python3 - <<'PY'
import pathlib
for l in pathlib.Path(".env").read_text().splitlines():
    if l.startswith("ISOLATION_A_API_KEY="):
        print(l.split("=", 1)[1].strip().strip('"').strip("'")); break
PY
)"
# 或者新发一把：venv/bin/python scripts/issue_api_key.py bench --days 7
```

⚠️ **鉴权头是 `X-API-Key`**（见 `app/main.py`）。
🔴 **⛔ 不用 `Authorization`** —— 原先的理由是「魔搭创空间那边平台会往每个请求注入它」；
⚠️ **那个平台已弃用**⇒ 🔵 **但结论保留**：本仓的取向是"**绝不读它、绝不回显它**"
（`docs/说明/魔搭创空间-部署与平台约束.md`，那份已加取代标记、只当实测事实读）。

### 2.3 跑

```bash
# ① 免费档（默认）—— 零花费，可反复跑
locust -f locust/locustfile_bench.py --headless -u 10 -r 2 -t 60s

# ② 付费档 —— 🔴 真调 embedding + 真打库，**每次请求都花钱**
BENCH_PAID=1 locust -f locust/locustfile_bench.py --headless -u 5 -r 1 -t 60s
```

⚠️ **用哪个 python**：本仓的 locust 装在 `./venv`（`venv/bin/locust`），
⛔ **别用系统 `python3`** —— 那个连本仓的依赖都没有。

## 三 · 两档：免费与付费

| 档 | 端点 | 开关 | 何时用 |
|---|---|---|---|
| **免费** | `/health` · `/agent/tool_versions` · `/agent/available_tools` · `/agent/budget/estimates` | 默认开 | **默认就跑这个** —— 它压的是**鉴权 + 中间件 + 路由 + 记账读侧**这条横切面 |
| **付费** | `POST /rag/search` | `BENCH_PAID=1` | 想看**真检索链**的表现时。🔴 **会花钱**（DashScope embedding），⚠️ **并发压小** |

⚠️ **诚实边界**：**免费档压不到 RAG / Agent 那条真链路**。
⇒ 它测得出"横切面（鉴权 + 限流中间件 + 路由）扛不扛得住"，
⛔ **测不出**"检索/生成在并发下的表现"—— 那要付费档，而付费档**不可反复跑**。

### 建议档位（⚠️ **本机是 8 GB / Docker 3.84 GB**）

| 并发 | 用途 |
|---:|---|
| **1** | 基线（单请求延迟） |
| **10** | ⭐ **主档** —— 裁定说的"不要太大" |
| **20** | 探饱和点 |
| **50+** | ⚠️ 只在**先看过 `docker stats`** 之后再上；本机很可能在那之前就顶到内存 |

⛔ **别照旧基线那样上 35 并发** —— 那三份数据的**错误率是 77% / 96% / 97%**（见下）。

## 四 · 🔴 旧基线为什么被废（`archive/性能基线报告模板-旧-20260625.txt`）

那份 2026-06-25 的模板里有三组数据（10 / 20 / 35 并发），**核心指标是**：

| 并发 | QPS | 平均延迟 | **错误率** |
|---:|---:|---:|---:|
| 10 | 5.1 | 14.73 ms | **77.24 %** |
| 20 | 10.5 | 8.32 ms | **96 %** |
| 35 | 17.8 | 7.72 ms | **97 %** |

🔴 **错误率 77%–97% ⇒ 那些 QPS 与延迟【没有意义】**
（"成功请求"只剩个位数百分比，延迟统计的是一堆**快速失败**）。
⚠️ 文件自己还写着「假设 20 是瓶颈，实际是**怕电脑加载出现故障没有做更高数值的高并发测试**」
—— 即"饱和点"那个结论**也没验过**。

⇒ 需求方裁定「**旧的不要**」⇒ 已移到 `archive/`（⛔ **没删** —— 它记着"当时试过什么"）。

📌 **本目录的用例专门防这个**：`locustfile.py` 的 `on_start` **开跑前先验一次鉴权**
⇒ 401 就**直接退出并说明原因**，⛔ 不让"全是 401"混进结果里当性能数据。
